# 机制设计：把"想象力"拆成可执行、可测量的步骤

> 术语约定：本文所有术语都使用认知科学与演化计算中的标准说法，首次出现给出英文原文。
> 自造词一律标注为"本文的操作化定义"，不与文献中的既有概念混用。
>
> 举一个容易误会的词：「算子」（代码与数据文件里的字段 operator）指的是创造力研究里的
> **技法（creativity technique）**——一条有出处、可执行的思考动作，比如 SCAMPER 的替代、
> TRIZ 的矛盾消解、结构映射的类比；它**不是**数学意义上的算子，也不是神经网络的算子。
> 正文提到算子时，都应读作"技法"。

## 1. 目标与判定标准

目标：设计一套"提示词 + Skill + 多子 Agent"机制，使 AI 在**开放式创意任务**上复现、甚至超过
人类水平的想象力/创造力/灵感，并且**可以被自动评分基准检验**。

判定标准不采用"看起来很有创意"这类主观说法，而采用创造力研究里的可操作定义：

| 维度 | 标准术语 | 本文的自动度量 |
| --- | --- | --- |
| 流畅性 | fluency | 去重并过滤后的有效想法条数 |
| 灵活性 | flexibility | 语义聚类簇数 / 词表类别数 |
| 原创性 | originality | 1 − 与"已知常见答案"语料的最大余弦相似度 |
| 具体化 | elaboration | 机制标记词 + 长度归一化 |
| 发散联想能力 | divergent association | DAT 计分：前 7 个有效词、21 对余弦距离均值 ×100 |
| 新颖性 | novelty | 1 − 与已知方案语料的最大余弦相似度 |
| 价值/可行性 | usefulness / feasibility | 独立 LLM 评委对每个配置同尺度打分（0-10，归一到 0-1） |
| 多样性 | diversity / coverage | 固定条数抽样的两两语义距离均值；质量-多样性档案覆盖率 |
| 同质化 | homogenization | 相对**其它配置**产出想法的区分度（撞车程度） |
| 聚合思维 | convergent thinking | RAT（远距离联想测验）至少一个候选命中的题目比例 |

"超过人类水平"在本文中只做**有限声明**：我们能在自动指标上比较不同机制，但不能声称超过人类，
因为本基准没有人类被试数据（见 docs/benchmark.md 的局限一节）。文献中可辩护的措辞是：
现有证据支持 LLM 在既定概念空间内高效完成**组合式/探索式**创造，而**变革式**创造仍缺乏独立验证。

## 2. 设计依据（每条设计都对应一条文献结论）

| 设计元素 | 文献依据（详见 docs/research-notes.md） |
| --- | --- |
| 用固定算子替代"请有创意" | SCAMPER/TRIZ 流水线在对照实验中有正面证据；"发散"指令本身不构成方法 |
| 生成者按算子异质化 | 头脑风暴的名义组（nominal group）优于互动组：独立探索 + 事后聚合优于实时互辩 |
| 不采用实时多 Agent 辩论 | 多智能体辩论的增益在多篇对照研究中不稳定，MAST 对 1600+ 轨迹的分析显示多数收益来自采样与投票 |
| 成对比较而非绝对打分 | AI co-scientist 使用锦标赛式成对排序；绝对打分容易分数膨胀 |
| 概念融合作为组合算子 | Fauconnier & Turner 的概念融合（generic space / blend / emergent）是明确的组合式创造模型 |
| 质量-多样性档案（MAP-Elites） | QD 算法用 coverage + 每格最优质量替代单一最优，天然对抗模式坍塌 |
| 升温必须绑定换算子 | 实验证据显示温度与新颖性仅弱相关、与不连贯性中等相关：温度不是创造力开关 |
| 双列交付 novelty 与 usefulness | 创造力的标准定义 = 原创性 + 适用性；只优化语义距离会奖励噪声 |
| 元反思（meta-reflection） | 对同质化的显式诊断；文献中 LLM 输出同质化（"人工蜂巢思维"）是可测量的普遍现象 |
| 交叉验证的自动评分 | 自动评分与人类评分一致性有限（κ 区间解释），必须报告度量方式与局限 |

## 3. 三层结构

```
┌─ 提示词层（prompt protocol）───────────────────────────────────────────┐
│  生成者提示词 = 任务 + 认知算子 + 角色 + 随机刺激词 + 已知方案清单      │
│                  + 可继承精英 + 禁止重复清单 → JSON                    │
│  评审提示词   = 三条 0-10 评分 + 一条最关键失败原因                    │
│  融合提示词   = generic space → blend → emergent → risks              │
│  元反思提示词 = 同质化诊断 + 下一轮算子建议 + 额外约束                 │
└───────────────────────────────────────────────────────────────────────┘
                 ↓ 由 Skill 固定下来（skills/creativity-engine/SKILL.md）
┌─ 多 Agent 层（roles）─────────────────────────────────────────────────┐
│  生成者 ×4（算子×角色×刺激词，互不相同）                               │
│  评审者 ×1（找漏洞，给 feasibility/novelty/impact + failure_mode）      │
│  融合者 ×1（跨档案格配对，概念融合）                                   │
│  元反思者 ×1（诊断套路重复，提出下一轮算子）                           │
│  自适应控制器（代码而非 Agent）：平均两两语义距离 < 阈值 → 升温 + 换算子  │
└───────────────────────────────────────────────────────────────────────┘
                 ↓ 每轮产出的想法进入
┌─ 质量-多样性档案层（archive）─────────────────────────────────────────┐
│  描述符：新颖度 × 可行性 → 3×3 网格；每格只留 objective 最高的一条     │
│  交付：精英集合（覆盖多格），而不是单一"最佳想法"                      │
│  指标：coverage、QD-score（每格目标值之和）                            │
└───────────────────────────────────────────────────────────────────────┘
```

数据流（一轮）：

```
任务 + 已知方案语料
   │
   ├─► 抽样"必须避免"的已有想法 ─┐
   ├─► 取档案精英作为种子 ────────┤
   │                              ▼
   └──────────────► 生成者₁..₄（不同算子/角色/刺激词） ──► 新想法
                                   │
                    近重复过滤（token Jaccard ≥ 0.82 丢弃）
                                   │
                    语义描述符计算（新颖度 = 1 − 与已知方案的最大余弦相似度）
                                   │
                    评审者：feasibility / novelty / impact / failure_mode
                                   │
                    归档：每个 (新颖度, 可行性) 格子保留 objective 最大者
                                   │
                    融合者：跨格配对 → 概念融合想法 → 同样过滤并归档
                                   │
                    测量：平均两两语义距离、簇数、新颖度、档案覆盖率
                                   │
                    若平均距离 < 0.35：温度 +0.15 且下一轮重新抽取未用算子
```

## 4. 为什么这些设计能提高"想象力"指标

1. **算子异质化**提高灵活性（flexibility）：不同算子探索的是不同的邻域；
   同一算子的多次采样只会得到同义词变体。消融配置 `engine-flat` 正是为了验证这一点。
2. **近重复过滤 + 强制"必须避免"清单**提高有效流畅性：条数多但互相重复不算流畅。
3. **以已知方案语料为参照的 novelty**把"原创"从修辞问题变成几何问题：
   改词不改意思的"伪原创"不会得分。
4. **评审者的失败原因**提供 usefulness 一列，避免出现"新颖但不可能"的噪声集合。
5. **质量-多样性档案**把"公平比较"和"防止模式坍塌"变成同一个结构：
   格子覆盖不足会直接反映在 coverage / QD-score 上。
6. **自适应控制器**只在检测到同质化时介入，并且绑定"换掉算子"而不是单纯升温，
   避免温度—连贯性权衡（temperature–coherence trade-off）把输出推向胡言乱语。

## 5. 反模式（与消融实验对应）

| 反模式 | 为什么错 | 对应消融 |
| --- | --- | --- |
| "请有创意/请发散" | 没有算子就没有方向，模型回到训练分布最顺手的套路 | zero-shot |
| 所有生成者同一角色同一算子 | 采样聚合的收益会被同质化吃掉 | engine-flat |
| 只保留 top-1 | 单目标筛选压缩灵活性，最终得到一个中位数答案 | 档案 vs 无档案（未来工作） |
| 实时互辩 | 对照证据不稳定，且成本高 | 本机制不使用辩论 |
| 用温度代替方法 | 温度与新颖性弱相关，与不连贯中等相关 | engine-noadapt / engine |
| 只报一个总分 | 掩盖 novelty-usefulness 权衡 | 双列指标 + 相关性 |

## 6. 已知局限

- 自动评分与人类评分的一致性有限；本文所有分数都是**自动指标的分数**，不等于人类评审结论。
- 样本量小（每个任务一次运行、种子固定），结论只能作为**机制可行性证据**，不是统计显著性结论。
- embedding 模型（qwen3-embedding）本身带有训练语料的偏好，会压制某些类别的新颖性；
  因此新颖度指标始终与"随机词基线"一起报告。
- 本基准不含人类被试，无法给出"超过人类水平"的结论。
- 未做多模型鲁棒性检验（所有结果来自同一个本地模型端点）。
