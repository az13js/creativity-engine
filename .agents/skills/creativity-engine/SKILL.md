# 创造力引擎（Creativity Engine）

这份文件可以单独拷到任何项目或任何 Agent 里使用，**不依赖本仓库的代码**：算子表、提示词模板、自检方法都写在下面。
仓库里的实现只是把同一套协议自动化了（跑批量任务、自动算分），没有它也能按下面的步骤手工做。

这套 Skill 的目标不是让模型"显得有创意"，而是把想象力拆成可执行、可检查的步骤：
**异质算子发散 → 严格评审 → 概念融合 → 质量-多样性策展 → 元反思纠偏 → 以组合而非单一答案交付**。

它的两个可检验标准来自创造力研究：
- **发散思维四维度**（Guilford 1967；Torrance 1966）：流畅性（fluency，有效想法数量）、
  灵活性（flexibility，类别数）、原创性（originality，相对常见答案的新颖程度）、
  具体化（elaboration，机制细节）。
- **新颖性与价值的权衡**：想法必须同时远离已知方案（novelty）且可用（usefulness/feasibility）。

## 何时使用 / 何时不用

**使用**：需要新方案、新用途、新假设、新命名、新切入点；已知方案都不满意；问题开放、约束可商量。

**不用**：答案唯一或有明确检索路径的事实性问题；用户已给出明确规格只需要执行；
风险不可逆的操作决策（此时优先级是安全与合规，而不是发散）。

## 核心协议（按顺序执行，可裁剪）

### 0. 任务框定（Preparation，Wallas 四阶段的第一步）
写下四件事，缺一不可：
1. **目标**：要改变什么状态；
2. **硬约束**：物理、法律、成本、时间上不可违反的条件；
3. **评价维度**：这次按什么排序（例如"新颖 > 可行 > 成本"），并写出 2-3 个会被判为"套话"的样板答案；
4. **已知方案清单**：列出 5-15 个已经被广泛提出的解法（我会用它们来计算新颖度，并明确要求生成者避开）。

> 没有已知方案清单，就无法区分"原创"和"信息缺失"。

### 1. 算子分发（Divergent preparation）
从下面的**认知算子**中选 3-6 个互不相似的分发给不同的生成者（每个生成者一个算子，不要叠加）。
算子必须被显式写进提示词，并禁止越出算子范围泛泛而谈。

| 算子 id | 名称 | 做法 | 来源传统 |
| --- | --- | --- | --- |
| attribute-substitution | 属性列举与替换 | 列出材料/形状/重量/成本/交互方式，逐个替换 | 属性列举法（Crawford 1931）、SCAMPER-Substitute |
| combination | 组合创造 | 与另一领域对象强制组合，写出共享抽象结构 | SCAMPER-Combine、概念融合 |
| analogy-transfer | 类比迁移 | 抽象出关系结构，到生物/工程/社会找同构机制 | 结构映射（Gentner 1983）、Synectics |
| constraint-inversion | 约束反转 | 列出默认假设，逐条反转或删除 | 横向思维（de Bono 1970）、TRIZ |
| extreme-scale | 极端尺度 | 参数推到 0.01×–1000×，看问题怎么变形 | TRIZ 尺度变换 |
| random-stimulus | 随机刺激 | 给一个无关名词，先找 3 个共同特征再出发 | 随机输入（de Bono 1970） |
| perspective-shift | 视角切换 | 用指定角色的约束和价值观重看问题 | 六顶思考帽、多角色提示 |
| re-representation | 重新表征 | 换一种表达（草图/方程/故事/极端案例）再解 | 问题空间重构；Wallas 孕育期 |
| contradiction-resolution | 矛盾消解 | 找一对冲突要求，在时间/空间/条件上分离 | TRIZ 矛盾矩阵 |
| reverse-brainstorming | 反向头脑风暴 | 先设计最糟方案，再逐条反转 | 反向头脑风暴 |
| cross-domain-transfer | 跨领域迁移 | 取一个无关行业的成熟机制迁移过来 | 类比迁移、TRIZ 跨行业类比 |
| function-decomposition | 功能分解与重组 | 删/并/重排/外包功能单元，形成新架构 | 价值工程功能分析 |

### 2. 异质发散（Divergence）
对每个生成者发出一份提示词，包含：任务 + 算子 + 角色 + 随机刺激词 + 已知方案清单 + 上一轮最优想法（可继承但要改进）。
要求：每条想法写成 **「手段 + 机制 + 预期效果」** 一句话；条与条之间思路必须不同；
输出 JSON，不要解释。

### 3. 技术评审（Convergence, part 1）
把一轮新想法交给一位**严格评审**：给 feasibility 0-10、novelty 0-10、impact 0-10，
并写出**一条最关键的失败原因**（failure_mode），找不到写 none。评审必须被要求"找漏洞"，
否则它会礼貌地全部打高分。

### 4. 概念融合（Convergence, part 2）
从上一轮里挑出位于**不同类别/不同档案格**的想法两两配对，让融合者按概念融合框架输出：
通用空间（generic space）→ 融合方案（blend）→ 涌现性质（emergent）→ 风险（risks）。
跨类别配对是重点：同类想法的融合只会得到折中方案。

### 5. 质量-多样性策展（Archive）
维护一个按描述符（新颖度 × 可行性）分格的档案，**每格只留最好的一个**。
最终交付的是档案里的精英集合（覆盖多个格子），不是单个"最佳想法"。
这一条直接对抗大模型的同质化倾向：单目标优化会把所有想法压成同一个套路。

### 6. 元反思与升温（Mode-collapse guard）
每轮结束后测量**平均两两语义距离**（把想法向量化后两两余弦距离求平均）与**类别数**。
- 若平均距离低于阈值（经验值 0.35），说明开始同质化：温度 +0.1~0.2，重新抽取未用过的算子，
  并在下一轮提示词里加入"上一轮在重复哪类套路"的诊断。
- 若距离正常，让元反思者指出尚未探索的空白方向，作为下一轮的额外约束。

### 7. 收敛交付
最后输出：
- **精英组合**：每个档案格 1 条，标注 novelty/feasibility/impact；
- **被淘汰的套路**：说明哪些常见答案已被有意避开，避免读者误以为是新意；
- **验证缺口**：每条精英的失败模式与下一步该用什么实验证伪。

## 提示词模板

生成者（每个算子一份）：
```
你是一名发散思维生成器，只负责产出候选想法，不做取舍。
【任务】{task}
【本轮认知算子】{operator_name}（{operator_origin}）
{operator_instruction}
【采用视角】{persona}
【随机刺激词】{stimulus}
【已知方案，必须避开】{known_solutions}
【可继承并改进的已有最优想法】{seeds}
【附加约束】{extra}
【产出要求】{n} 条互不相同的想法，每条写成「手段 + 机制 + 预期效果」。
只输出 JSON：{"ideas":[{"idea":"...","rationale":"..."}]}
```

评审：
```
你是一名严格的技术评审。你的职责不是鼓励，而是找出具体漏洞。
对每条想法给 feasibility / novelty / impact（0-10）与一条最关键的 failure_mode，找不到写 none。
只输出 JSON：{"reviews":[{"index":1,"feasibility":0,"novelty":0,"impact":0,"failure_mode":"..."}]}
```

融合者：
```
你是一名概念融合器。给定两个来自不同思路簇的想法，按概念融合框架输出：
generic_space（两者共享的抽象结构）、blend（叠加后的方案）、emergent（任一方都不具备的新性质）、risks。
只输出 JSON：{"generic_space":"...","blend":"...","emergent":"...","risks":"..."}
```

元反思者：
```
你是一名元反思者。看统计与抽样文本，判断这一轮是否在重复同一类套路。
输出 {"diagnosis":"...","recommended_operators":["..."],"recommended_note":"..."}
```

## 反模式（观察到就立即纠正）
- 只说"请有创意/请发散"：没有算子与约束，模型会回到训练分布里最顺手的套路。
- 全部生成者用同一个角色：角色是"同质化"的主要来源之一，必须配合算子一起异质化。
- 只保留一个"最佳"：单目标筛选会牺牲灵活性，最后得到的是一个中位数答案。
- 评审只打分不给失败模式：评分会通货膨胀，无法用于筛选。
- 用字数、修辞或生僻词代替新意：新颖度必须相对**已知方案语料**测量，而不是相对措辞。
- 无限制升温：温度过高会退化为随机字符串，升温必须与"换算子"绑定。

## 机检与自检
如果手边有本仓库，可以直接跑同名实现与基准（`node scripts/bench.ts`）；没有也没关系，下面这些指标都能手工近似：
- AUT（Alternative Uses Test）：流畅性/灵活性/原创性/具体化 + 综合指数；
- DAT（Divergent Association Task）风格：词对平均语义距离；
- 设计简报：相对已知方案语料的新颖度、想法间语义距离、簇数；
- 逐轮过程指标：每代平均两两距离与簇数，用于观察是否模式坍塌。
若没有本仓库，也可以手工近似：把想法向量化，算"1 − 与已知方案的最大余弦相似度"作为新颖度，
算"两两余弦距离均值"作为多样性，算"聚类簇数"作为灵活性。
